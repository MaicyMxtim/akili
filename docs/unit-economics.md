# Costs

Akili runs on a laptop for nothing. That is the point of the exercise, but it is not an argument that managed services are wasteful. This document works out what the same capabilities cost when bought, and at what scale buying starts to make sense.

Prices are indicative US list prices for a single region and should be re-checked before quoting them anywhere. They are here to establish orders of magnitude, not to be precise.

## Capabilities

| Capability | Akili component | Managed equivalent |
|---|---|---|
| Kubernetes control plane | k3d on the laptop | EKS or GKE control plane |
| Pipeline orchestration | Argo Workflows | Managed Airflow (MWAA) or Step Functions |
| Experiment tracking and registry | MLflow with Postgres | Databricks or SageMaker model registry |
| Object storage | MinIO | S3 |
| Model serving | FastAPI behind Argo Rollouts | SageMaker real-time endpoint |
| Feature store | Feast with Redis | SageMaker Feature Store or Tecton |
| Metrics, logs, dashboards | Prometheus, Loki, Grafana | CloudWatch or Datadog |
| Container registry and CI | ghcr and GitHub Actions | ECR and CodeBuild |

## Monthly cost if bought

| Line | Assumption | Monthly |
|---|---|---|
| EKS control plane | $0.10/hr | ~$73 |
| Worker nodes | 2 × m5.large on demand | ~$140 |
| Managed Airflow | smallest environment | ~$350 |
| Managed feature store | modest online store | ~$100 |
| SageMaker endpoint | 1 × ml.m5.large, always on | ~$84 |
| Object storage | tens of GB | ~$5 |
| Observability | Datadog, few hosts | ~$100 |
| **Total** | | **~£650 to 700 per month** |

The equivalent self-hosted-on-cloud version, which is what Tamani did, is a single small EC2 instance running k3s at roughly £25 to 30 per month. Akili on a laptop is the electricity, call it £2 a month if it ran continuously, which it does not.

So the spread across the three options is roughly 300x from bottom to top.

## Cost drivers

Two lines dominate: managed Airflow and observability. Together they are more than half the bill, and both are the components a small team is most tempted to buy because operating them is genuinely fiddly. The compute for training this model is negligible, a LightGBM fit over 780,000 rows takes about ten minutes on shared CPU, which is a few pence of EC2 time.

That inverts the intuition people carry from working with large models. For a tabular workload of this size, **the platform costs far more than the machine learning**. The model could be trained on a phone. What costs money is the surrounding apparatus that makes retraining safe and repeatable.

## Buy or build

Managed services are worth it when engineer time is the scarce resource rather than money, which is most of the time in a funded company. The crossover is roughly:

- **Below one or two ML engineers**, buy nearly everything. £700 a month is a rounding error against a salary, and the alternative is one person maintaining nine open source components.
- **Two to five engineers with several models**, a hybrid works: managed Kubernetes and object storage, self-hosted tracking and orchestration on top. That is where most of the benefit sits with the least operational burden.
- **Beyond that**, self-hosting the middle of the stack pays, because the managed alternatives price per pipeline or per endpoint and the bill grows faster than the team.

The honest summary for this project: I built it all myself to learn what each piece does and what breaks. A company at this scale should not.

## Effects of the hardware limit

Running everything on eight cores forced decisions a generous budget would have hidden:

- Every component's memory limit had to be justified, and three of the four incidents in this project were memory exhaustion. On a cloud cluster with headroom they would have gone unnoticed until much later and at larger scale.
- The Argo CD controller needed 512Mi at four applications and 1.5Gi at thirteen. That growth curve is invisible until something enforces it.
- A fail-closed admission webhook that cannot start takes the entire cluster with it. Discovering that on a laptop cost an evening. Discovering it in production costs an outage.

## Data durability

Deleting and recreating the cluster destroyed the MinIO volumes and the MLflow database, because both sit on local-path storage backed by the node containers. The platform rebuilt itself from git in about fifteen minutes, but every trained model, dataset version and signature was gone and had to be regenerated by rerunning the pipelines.

That is a real gap, and worth stating plainly: **the platform is reproducible, the data is not.** A production deployment needs object storage on durable media, scheduled database backups, and a restore procedure that is tested rather than assumed. On managed services this is bought by default with S3 and RDS, which is a large part of what the money in the table above is actually for.
